# playbook 卡片格式規格

本檔是提案用的自包含規格。一主題一張卡，內容是精簡的「適用情境＋可執行檢查事項＋必要來源／版本」，方便做功能時快速檢查。

## 收什麼

只收已確認可行的提醒與做法；不收研究筆記、推測、方案比較或一般教學。素材不足就詢問使用者，不補造事實。

依功能情境表達，例如「PDF 處理」先提醒確認套件，再列使用 pdf.js 時的條件式檢查。避免把特定套件的條件當所有實作的通則。

## 位置與檔名

- `cards/<slug>.md`，平鋪，不開子資料夾；slug 為 ASCII 小寫英數與 `-`，以情境或工具命名。
- 已有同主題正式卡就更新，沿用 slug；如 `pdfjs-cjk-cmap.md` 可保留檔名、以「PDF 處理」作 title。
- 保留正式卡與 open PR 的去重及使用者審核流程；未合併提案須標「未接受」。

## frontmatter

五個欄位都必填，依原順序保留：

| 欄位 | 格式 | 規則 |
|---|---|---|
| `title` | 字串 | 清楚的功能情境／主題，可中文 |
| `description` | 字串 | 一句話涵蓋情境與檢查重點；涉及特定套件時包含套件／工具名以輔助搜尋 |
| `tags` | YAML list | 小寫、`-` 連接，含情境詞及相關套件／症狀 |
| `created` | `YYYY-MM-DD` | 建立日；更新時不改 |
| `updated` | `YYYY-MM-DD` | 最後修改日；新卡與 created 相同 |

## 正文

繁體中文，技術名詞保留英文。以情境／主題標題與短檢查清單組成：

- **適用情境**：何時要檢查；可放在標題或首條提醒。
- **可執行檢查事項**：能實際確認、設定或驗證的動作；將套件、環境及例外條件放在對應項目。每項保留必要理由即可。
- **必要來源／版本**：技術事實列官方一手來源於 `## 來源`；版本影響做法時，在對應項目或來源標明查證版本。

不硬限制行數，以足以執行的精簡提醒為準；不要求「問題／做法／原因」長篇章節、完整程式碼或教學。必要的參數與路徑可用行內 code。

## 事實查證

API 名、參數、預設值、版本行為須對官方文件、release notes 或原始碼，並列來源。查不到的事實不寫進卡片，改列 PR 說明的「未查證」。不要用格式範例當已查證內容。

## 範例

```markdown
---
title: PDF 處理
description: 涉及 PDF 解析或顯示時確認套件，使用 pdf.js（pdfjs-dist）時檢查資源路徑並用中文 PDF 驗證。
tags: [pdf, pdfjs-dist, cjk, cmap]
created: 2026-10-08
updated: 2026-10-09
---

## PDF 處理

- 涉及 PDF 解析或顯示時，先確認使用的套件。
- 使用 pdf.js（`pdfjs-dist`）時，依 PDF 的 CMap／未內嵌字型需求檢查資源與路徑；瀏覽器驗證 URL 可存取，Node.js 驗證本機路徑可讀。
- 用中文 PDF 驗證顯示沒有缺字；有文字解析功能時也檢查解析結果。

## 來源

- [pdf.js 參數（查證版本 v6.4.299）](https://github.com/mozilla/pdf.js/blob/v6.4.299/src/display/api.js)
```

寫入目標 repo 前讀其 AGENTS.md；若仍要求舊版長教學／完整 code，回報與本規格的衝突，不自行修改 AGENTS.md 或重構卡片庫。使用者的明確指示優先；未有明確指示時先釐清衝突再寫卡。
